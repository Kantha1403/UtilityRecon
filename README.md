# UtilityRecon: Multi-Vendor Bill Validation & Reconciliation Pipeline

A simulated revenue-operations pipeline that ingests messy, inconsistent utility invoice data from multiple vendors, normalizes it, reconciles it against payment records, flags anomalies, and surfaces everything on an interactive dashboard — mirroring the exact workflow a Data/Revenue Ops Analyst runs in production.

## What this project does

- Ingests invoice data from 4 vendors, each with a different schema, date format, unit of measurement, and currency
- Cleans and normalizes all four into one unified table, explicitly flagging data-quality issues instead of silently fixing them (missing values, negative readings, duplicates)
- Reconciles ~240,000 invoices against a payment ledger in SQL, identifying missing invoices, amount mismatches, and overdue payments
- Runs per-vendor statistical anomaly detection (Z-score) on consumption and billed amount
- Presents everything on an interactive Streamlit dashboard with vendor and date-range filtering, a CSV export, and a vendor health ranking

## Key findings

- **₹790.6M** total billed across 240,000 invoices
- **7,182 invoices (2.99%)** billed but missing from the payment ledger
- **215 invoices** with amount mismatches greater than ₹50 between billed and paid
- **4.47%** of all invoices flagged for manual review across 6 data-quality checks
- **85.26%** SLA on-time payment rate

## Tech stack

- **Python** (pandas, numpy) — data generation, cleaning, normalization, anomaly detection
- **MySQL** — reconciliation via SQL joins and aggregations
- **Streamlit** — interactive dashboard

## Project structure

- `UtilityRecon.ipynb` — full pipeline: data generation → cleaning → reconciliation → anomaly detection → KPI calculation
- `dashboard.py` — Streamlit dashboard (reads from files generated by the notebook)

## How to run

1. Run all cells in `UtilityRecon.ipynb` — this generates the synthetic vendor data and produces the cleaned CSVs and KPI files the dashboard reads from
2. Update the MySQL password placeholder in the notebook with your own local MySQL credentials
3. Run the dashboard:

```
   streamlit run dashboard.py
```

## Notes

- Data is fully synthetic, generated to simulate realistic messiness: mixed date formats (including Excel serial dates), currency contamination, unit mismatches (MWh vs kWh, USD vs INR), duplicate records, and missing values
- The exchange rate and anomaly thresholds are hardcoded for this simulation; a production system would pull these from a live source.
